07 · Technical Learnings
What This Project Demonstrates

Data Quality as the Foundation

No analytical output is more reliable than the underlying data. Systematic cleaning — null imputation, duplicate detection, type enforcement — established the integrity needed for accurate downstream querying and reporting.

Python → SQL → BI as a Stack

Each tool plays a distinct role: Python for flexibility and exploration, SQL for structured logic and scale, Power BI for communication. Their sequential use yields results none could produce alone.

Schema Design Drives Query Speed

A normalized schema with indexed foreign keys reduced query execution time significantly on larger datasets. Design decisions made early directly impact the analytical performance of the entire system.

Visualization Drives Action

Power BI transformed raw SQL output into KPIs stakeholders could immediately interpret. Choosing the right chart type and slicer configuration is as important as the underlying data calculation.

Inventory Thresholds Need Context

A static reorder level does not account for demand seasonality. EDA revealed that some "low stock" alerts occur during predictable demand dips, recommending dynamic thresholds in future iterations.

Vendor Concentration Risk

Two vendors account for 54% of total supply volume. This dependency was only surfaced through data — highlighting a procurement risk that manual reporting had not previously flagged.

Project Conclusion

The Vendor Inventory Analysis System successfully demonstrates how Python, SQL, and Power BI can be integrated into a unified end-to-end analytical pipeline. By transforming fragmented procurement data into actionable insights, the system enables organizations to reduce stockouts, eliminate inefficient overstock, benchmark vendor reliability, and make data-driven sourcing decisions at scale.

The architecture is modular and extensible — ready for future enhancements including ML-based demand forecasting, real-time data pipelines, predictive vendor scoring, and cloud deployment on Azure or AWS.

Python

EDA surfaced vendor concentration risk, stock status distribution, category value splits, and reorder threshold violations from raw transactional data.

SQL

Normalized schema design and analytical queries validated EDA findings and enabled high-performance aggregation across vendor, product, and inventory tables.

Power BI

Interactive dashboards translated technical outputs into executive KPIs, real-time low-stock alerts, and vendor ranking visuals for stakeholder decision-making.
